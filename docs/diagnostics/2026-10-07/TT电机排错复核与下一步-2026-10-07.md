# TT 电机 / TB6612 排错复核与下一步
日期：2026-10-07（Asia/Shanghai）

审查快照：x1shang/Chariot_strom_of_gear，master 的 c76249435cf63825123c24b832abb2f966b35686。
本次读取远端文档、源码和原始日志，并对软启动过程做了软件计算；未编译、烧录、打开串口或操作实物。没有修改现有程序。

## 1. 当前结论

现车是四个无编码器、两根动力线的 TT 电机，用户给出的额定电压为 3–6V、标称空载电流为 140mA（对应电压未知）。
因此现车不执行 CPR 标定、编码器中断测试，也不能从串口生成真实 rpm。
本地编码器台架方案不适用现车；仓库已有《TT两线电机与麦轮分层验收》对此作了正确修订。

按排错对话最新反馈：
- 一台电机独立直供能够转动：只证明该台在当次条件下能够启动，不能证明四台、两种方向、驱动板或带载性能均正常。
- D1-B/RL 测得 VM–GND 约 6V，STBY–GND 约 3.3V。
- BIN1–GND 在约 1.6V 与 0V 间变化。
- BO1–BO2 显示 0V，电机不转。
- D1 当前 VCC、PWMB、BIN2、功率地路径及同条件 D2 对照还没有完整的新测量。

据此，最值得先查的是 D1-B 的 PWM 常高供电、另一方向输入、逻辑供电、器件端连线和地回路。尚不能定案为坏板。

## 2. 哪些推断需要收紧

### 测得 VM=6V 不能证明功率地回路合格
若黑表笔在电源公共地，红笔测 VM，即使驱动板地线断开也可能读到 6V。
即便测的是模块 VM 与模块 GND，万用表只取很小电流；有读数也不能证明这条路径能承受电机启动电流。
断电核对模块所有使用的 GND 到公共地端子的实际路径，并在运行时看模块地相对电源负极的压降、VM 动态和电源 CC 指示。

### BIN1 平均约 1.6V 不是“20kHz、50% 波形正确”的认证
这支持该测点有变化，但不能证明波形幅值、频率、脉宽或整段测量正确。
测面包板侧也不能证明信号已到模块针脚。
BIN2 若也有同相波形，两个输出可能始终同电位，差分读数为零。

### BO1–BO2=0V 不能直接判坏板
候选原因包括 PWMB 未拉高、VCC 缺失、BIN1/BIN2 接错或同相、测错输出对、输出短接、连接/地问题、欠压或热关断，以及模块损伤。
高阻、短路制动、两端同电位都可能读零；需要先建立完整的输入条件。
“只有两种情形”的判断不成立。

### 保护功能不能靠猜
东芝手册明确列出热关断与低压检测，不能据此假设存在可依赖的过流保护或过流锁存。
此前 VM=12V 对 3–6V 电机不合适，可能带来损伤风险；不能由此直接认定驱动芯片已坏。
停止测试后断电、待冷却再复测有诊断价值，但复测通过不等于恢复了全部性能。

## 3. 程序审查发现

### 现车控制方式与本地测试程序不同
现车：
- FL：GPIO16/17 → D1 AIN1/AIN2；
- RL：GPIO18/19 → D1 BIN1/BIN2；
- FR：GPIO23/32 → D2 AIN1/AIN2；
- RR：GPIO15/5 → D2 BIN1/BIN2；
- STBY：GPIO33，共用外部 10kΩ 下拉；
- 四个 PWMA/PWMB 固定接 3.3V，调速 PWM 在 IN 引脚上。

本地 tb6612_bringup_test.ino 使用 GPIO25/26/27 → PWMA/AIN1/AIN2，属于另一套接线。
25/26/27 在现车分配给投掷驱动；18/19 在现车是 RL 控制，不是编码器输入。
因此不能按现车接线直接烧录本地程序。优先沿用现车接线定义，把测试条件简化。

### 重复点动并不是持续 50%
DriveMath.h 每次 10ms 最多增加 3 档。由 0 到 128 需要约 43 次更新，即约 430ms。
- 400ms 点动没有形成 128/255 平台。
- 800ms 点动只有约后 370ms 在目标附近。
- jog_loop.py 每次结束后重新点动，从零再次爬升；约 60ms 间隙之外，还有整段爬升。

按理想 10ms 调度计算，800ms + 60ms 周期中 IN 的时间平均占空比约 34%，不是持续 50%。
真实读数还受调度、表计刷新和采样窗口影响。这是输入占空比估算，不是电机电压或转速的测量。
两线法 PWM 关闭阶段为滑行，高阻期间输出电压还受绕组电流和反电动势影响，不能把差分表读数必须约 3V 当作硬判据。

### jog_loop.py 的停止表述不准确
脚本会在后续周期继续发送 JOG。若在脚本仍运行时用别的途径发一次 STOP，下一次 JOG 仍可能再次启动。
该脚本也不会看到 ERR 就自动退出；退出时尝试发送 STOP，但异常路径不保证成功，更没有严格核验停止回复。
同一个串口通常不能同时由另一个串口监视器打开。
诊断时应结束重复发送脚本，并保留物理断电；不要把一次 STOP 等同于取消整个循环。

### 本地 bring-up 的几个问题
- fullSpeed() 仍通过 LEDC 写满占空比，并未脱离 PWM 外设；“纯数字绕过 PWM”的表述不准确。
- 自动测试大量使用 delay，整个序列约 19 秒；期间 loop 不处理 x 停止命令。
- allOff() 令两个 IN 低且 PWM 为 0；按手册这不是所宣称的高阻滑行。要滑行，可 STBY 低，或 STBY 高、PWM 高、两个 IN 低。
- 手动驱动没有限时，换向没有停稳阶段；解析负数后转换为 uint8_t 还可能变成大占空比。
这些是暂不使用它替代现车排错程序的理由。本次未改此文件。

## 4. 建议下一步：保留现有共地，先补 D1-B 板端测量

### 当前执行单（地线初查后更新）
详细执行步骤见 [D1-B输入补测-逐步操作单](D1-B输入补测-逐步操作单.md)。本地已准备 host/jog_loop.py（原协议，更新提示），可按该操作单在当前文件夹安装串口组件后运行，不必再进入队友的仓库文件夹。未运行硬件测试。
用户实测表笔短接底数 0.2Ω，D1/D2/ESP32 三个地测点为 0.3–0.7Ω；地网络为驱动板 GND → 面包板负轨 → 降压 OUT−。
这说明测量时已有共地导通，不证明地故障，也未认证启动电流下的压降。当前先保留此接线；下面的直接功率回线建议属于改善措施，不能当作已经找到故障。

1. 停止重复点动脚本，断开 USB、VM 和其他电源；投掷动力保持断开。
2. 拍照或标记后，将各电机的两根动力线从驱动输出拆下并分别绝缘，至少 D1-B 的 BO1/BO2 上不留电机。不改 IN/PWM/STBY 控制线，不改程序。
3. 恢复现有 MecanumPS2 的逻辑及 6V VM 供电，保持锁定。万用表切直流电压，黑笔接 D1 模块 GND，红笔在 D1 模块针脚分别量 VCC、PWMB：都应约 3.3V。任何一项异常先停止、断电查线，不继续判板。
4. 前两项正确后，在队友仓库根目录运行现有 host/jog_loop.py，选择 RL、128、20 秒（COM9 是历史端口，须使用当前正确端口）。仅为无电机的板端测量，不是带电机长跑。用模块 GND 作参考，测 STBY、BIN1、BIN2；STBY 应在有效点动期间高、间隙低，BIN2 应接近 0V，BIN1 应有输出变化。电压档不能认证波形，不要求 BIN1 必须稳定 1.6V。
5. 结束脚本，检查停止回复/锁定状态。回填 VCC、PWMB、BIN2 的读数，并说明是否在运行期间测量、BIN1/STBY 的变化。若 BIN2 也变化，优先查两方向线错位/短接；PWMB 或 VCC 不对则先修对应供电。
6. 输入补测没有异常仍不能立即判坏板。下一步按后文将主控控制线隔离后做无电机静态真值表测试，固定 IN 高低电平验证输出，必要时对 D2-B 做同条件对照。恢复电机前全部断电；负载测试恢复为 0.5–1 秒短测。

### 优先步骤：GND 回路检查（用户于 2026-10-07 指定）
先保持现车两线版 GPIO 分配，暂不改控制线、不重新烧录。

1. 拔掉 USB，断开 VM、电池/适配器及其他电源。全部断电后才用电阻或蜂鸣档。
2. 短接两表笔，记录表笔与接触的底数。以下测量应稳定、接近这个底数；蜂鸣器响不代表大电流连接合格。
3. 电机电源若来自降压模块，参考负极是实际供 VM 的 OUT−/公共地端子，不能未经核对就把 IN−当成同一点。
4. 一支表笔固定在上述负极，另一支依次测 D1 模块 GND、D2 模块 GND、ESP32 GND。驱动模块若有多个 GND 端子，逐个核对，尤其实际承担功率回流的端子；不必用探针碰芯片细脚。边轻动接头边看阻值是否跳变。
5. 两块驱动板分别应有能承载电机电流的直接回路线到公共地端子；不要让动力电流只经面包板地轨或 ESP32 的细共地线返回。ESP32 共地线用于控制参考，不能替代功率回路。
6. 测整体网络可能被其他连线绕路掩盖。某条线可疑时，标记后将该线两端拆下，单独测端到端电阻与接触；再断电恢复。若确认缺失或接触不良，断电修复后重复核对。
7. 断电检查通过后，切回直流电压档。黑笔接实际电机电源负极，红笔分别测 D1/D2 模块 GND，相对负极应接近 0V。在已有条件允许的短时单轮测试中观察是否出现明显压降；不转即停止，不延长堵转等读数。短脉冲下万用表可能漏掉压降，读零不是动态回路已认证。需要时用适合的仪器捕获。

优先回填：表笔短接底数、D1/D2/ESP32 到电源负极的阻值、是否稳定、两板动力地线实际走法。地回路核清后，再进入下述静态检验。

目的：消除 PS2、软启动、重复点动、表计刷新和电机启动负载的歧义。

### 第一步：全部断电，隔离 D1-B
1. 断开 VM、USB 及其他电源；投掷动力继续断开。
2. 标记并拆下 D1-B 的电机两根线，分别绝缘。不要在仍连接驱动输出的电机上并接外部电源。
3. 暂时把 D1 与 ESP32 的所有 IN、STBY 控制连线断开并标记，避免对仍被主控驱动的脚强接 3.3V/GND。
4. D1 与 D2 的 STBY 若共用桥线，本次隔离 D1 或同时切断 D2 VM，不能让 D2 因静态拉高一起使能。
5. 核对 D1 地、电源与输出没有错接。断电时才用通断/电阻档。
6. 用短的直接连线建立单板测试；逻辑 VCC 使用稳定的 3.3V，VM 使用已验证且匹配电机的 3–6V。若用 ESP32 3V3 供逻辑，仍需正确共地，但原 GPIO 控制线保持拆开。

### 第二步：先不接电机，用静态电平测输出
用明确的固定逻辑线，不用 PWM：
- VCC=3.3V；
- STBY=3.3V；
- PWMB=3.3V；
- BIN1=3.3V；
- BIN2=0V；
- VM=记录的实测值（例如 6V）；
- 逻辑/功率地按模块接法接回公共地。

所有电压在模块针脚测量；不要只测电源显示或面包板远端。

| 测点 | 正向静态设置的预期 |
|---|---|
| VCC–模块GND | 约 3.3V |
| VM–模块GND | 设定 VM |
| STBY–模块GND | 约 3.3V |
| PWMB–模块GND | 约 3.3V |
| BIN1–模块GND | 约 3.3V |
| BIN2–模块GND | 约 0V |
| BO1–模块GND | 接近 VM |
| BO2–模块GND | 接近 0V |
| BO1–BO2（红 BO1、黑 BO2） | 接近 +VM |

断开 VM 后交换 BIN1/BIN2 的固定高低电平，再上电复测；应 BO1 低、BO2 接近 VM，差分接近 -VM。
不要带电改接线；探针避免短接相邻针脚。电机尚未接入，这时可以稳定读表。

判读：
- 输入不符：先修电源/接线，不判坏板。
- 输入符合、无负载输出仍不符：检查输出短接、模块引脚定义、冷却后状态，再用 D2-B 和同一套电源/测试线作对照。
- 仅 D1-B 失败：定位为 D1-B 通道/模块区域故障的证据较强；还需区分端子、焊点、PCB 和芯片，不能把整块板所有通道一概判坏。
- 两板都失败：先查共同的测试接法、逻辑/功率电源和实际模块定义。
- 两板空载正常：转入电机负载短测，空载通过不代表能带电机。

### 第三步：接同一台已验证能转的电机，短时测试
全部断电后接入；用与独立直供可转时一致的电压和机械状态，先约 0.5–1 秒。
观察是否自主启动、VM 是否下降、模块地相对电源负极是否出现明显压降、电源 CC/保护与电流显示。
不转即停止，不用 30–300 秒重复通电等读数。

- 静态空载输出正常、带电机后失效：查电源电流能力、功率地和动力线接触、输出级损伤/热关断与机械负载。
- 静态直接接线带电机能转、恢复原控制后不转：查 IN/STBY 路径、面包板、GPIO 映射和实际波形。
- 改到 D2 同通道能够转：更支持 D1 通道/连接问题；必须使用同一电机和测试线，减少混杂因素。

有示波器/逻辑分析仪时可观察短测波形；用万用表测瞬态要保留“可能漏掉”的限制。逻辑分析仪不能直接接 VM/电机输出，应按仪器额定范围和测量方式操作。

## 5. 链路打通后的顺序
1. 用同一台电机验证四个通道，再逐台验证 M1–M4，记录实际轮位和正反向极性。
2. 恢复 MecanumPS2，确认两线法、轮位和 POLARITY；将“爬升时长”和“目标保持时长”分别记录。
3. 逐档做从静止启动与持续运行测试。维持转动的最低占空比与从静止启动的最低占空比是不同数据。
4. 架空验证 STOP、松 L1、圆圈锁定、重启及真实手柄断联。
5. 核对麦轮左右手位置，再做低速落地的前后/横移/旋转。
6. 稳定运行后再补电流、视频测速和温升。无编码器时 rpm=60N/t，t 为真实拍摄时长。
7. 最后处理投掷 AS5600 与动作互锁，不把当前底盘诊断与投掷故障混在一起。

当前固件 PS2 最大 76/255 约 30%。链路通过后若架空可转但落地无法启动，要测启动占空比与带载电流再调整上限，不能直接当成新接线故障；占空比上限也不是限流器。
