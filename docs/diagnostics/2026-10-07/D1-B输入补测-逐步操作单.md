# D1-B 输入补测：一步一步操作单
日期：2026-10-07。适用于现车两线版 MecanumPS2，四台 TT 电机无编码器。

## 本轮要得到什么
只记录 D1 模块上的 VM、VCC、PWMB、STBY、BIN1、BIN2 电压。
保留现有地线；不改 GPIO、不烧录程序、不装车试跑。
已有地线读数：表笔底数 0.2Ω，三个测点 0.3–0.7Ω。它们支持已共地导通，不能证明当前故障来自面包板。

本地文件夹原来没有 host/jog_loop.py，现已准备：
host/jog_loop.py。
该脚本基于已审查的队友仓库版本 c76249435cf63825123c24b832abb2f966b35686，仅更新用途提示、帮助和默认总时长。JOG/STOP 发送方式保持原样。已检查语法，尚未连接实物运行。
第4步已由 Codex 完成：本文件夹 .venv 已创建，pyserial 3.5 已安装，脚本 --help 已成功运行。未打开串口、未发送点动。可直接继续第5步。
后续实测更新：当前 CH340 串口为 COM4。已打开串口读取状态并发送 STATUS，连续返回 hw=1、ps=1、mode=41、buttons=0000、control=LOCKED、STBY=0、duty=0,0,0,0。串口已关闭，未发送运动命令。接收器与主控通信有效，手柄无线连接仍待按键变化确认。下文 COM9 是历史示例，当前应替换为 COM4。
按键实测续：用户按住圆圈键后，连续读到 buttons=2000；control=LOCKED、STBY=0、四轮指令为零。已确认该实体手柄的圆圈指令传到主控。释放恢复待检查；完成后可继续万用表设置与静止端子测量。
释放实测续：松开后连续读到 buttons=0000，仍LOCKED、STBY=0、四轮指令为零。第5步端口/固件/PS2输入检查已完成，可以继续第6–7步；未测试手柄无线断联行为。

## 第1步：彻底断电
1. 如果点动脚本仍在运行，点终端窗口，按 Ctrl+C。
2. 关闭 Arduino 串口监视器/串口绘图器及其他正在读串口的软件。
3. 拔下 ESP32 的 USB。
4. 断开给降压模块供电的电池或适配器，不只是暂停串口命令。
5. 投掷电机驱动的动力继续断开。
6. 此时才拆线。测电阻/蜂鸣只能在全部断电时进行；后面测电压不再用这两个档位。

## 第2步：拆开电机，保留控制接线
1. 拍一张能分辨电机端子和线色的照片，或用胶带标记每对线。
2. 将四台电机的两根动力线都从 AO1/AO2、BO1/BO2 输出端拆开；每根裸露端分别绝缘，避免线头碰在一起。
3. 尤其确认 D1 的 BO1、BO2 上已没有电机连接。
4. 保留 VM、VCC、PWMA/PWMB、STBY、AIN1/AIN2、BIN1/BIN2、GND 的现有连接。
5. 不把电机线改接 GND，不拆共地网络，不安装本地三线测试程序。

这样脚本重复输出时没有电机负载，允许留出时间读表。这不是带电机长跑流程。

## 第3步：认清 D1 与测点
不要凭板子“在左边”猜编号，沿现有连线核对：
- GPIO18 → 该模块 BIN1；
- GPIO19 → 该模块 BIN2。
符合这两条的是本轮的 D1，测它的 B 通道。固件标签为 RL。

只按模块丝印找这些针：
GND / VM / VCC / PWMB / STBY / BIN1 / BIN2。
PWMB 是输入；BO1、BO2 是输出，不能混淆。
测的是针脚上的金属，不是塑料插头外壳。用细探针或夹子，避免同时碰到相邻针。

找不到丝印、无法确定模块或探针放不稳时，先断电，不猜位置通电试探。

## 第4步：准备电脑软件（尚不接电机动力）
**已完成，可跳过本节。** 以下命令保留作以后重新准备环境时的参考。
1. 打开 PowerShell。
2. 复制并执行下面各行，一次执行一行：

```powershell
# 在仓库根目录执行以下命令
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install pyserial
& '.\.venv\Scripts\python.exe' '.\host\jog_loop.py' --help
```

前两行建立本文件夹专用的 Python 环境；第三行安装串口组件，需要联网；不用执行 Activate，也不用修改 PowerShell 执行策略。
最后一行应打印用法，不会打开串口或发送点动。
任何一行报错就保存完整错误，不跳过它直接试硬件。依赖安装若网络失败，先解决安装，不重复修改接线。

## 第5步：插 USB，确认串口与固件
1. 暂时仍不打开 VM 动力电源，插回 ESP32 USB。
2. 开启 PS2 手柄，让接收器正常连接；所有按键松开，尤其不要按 START 或 L1。
3. 在同一 PowerShell 执行：

```powershell
& '.\.venv\Scripts\python.exe' -m serial.tools.list_ports
```

这条只枚举串口，不发送点动。
记录 CH340/USB-SERIAL 对应的 COM 号。COM7/COM8 等可能是其他设备，不能只凭编号选。
如果分不清，可以在 VM 仍关闭时拔 USB 看哪项消失，再插回看哪项出现；选对应端口。
下面示例用历史 COM9，若实际为 COM10 等，修改命令里的 COM9。

4. 需要检查板上固件时，打开 Arduino 串口监视器，选择对应端口、115200波特率、换行。发送 STATUS（英文大写）。
5. 期望看到包含：
```text
STATUS hw=1 ps=1 ... control=LOCKED STBY=0 duty=0,0,0,0
```
中间 mode/buttons 也会打印；这不是要求逐字完全相同。
- hw=0：初始化异常，不继续。
- ps=0：PS2 未满足在线条件，不继续点动，检查手柄/接收器。
- control=PS2 或 JOG：发送 STOP，等待 LOCKED。
- 返回其他固件名称、乱码或不支持 STATUS：保存原文，先确认固件；不要为了本操作单烧录本地三线程序。
6. 正常后关闭串口监视器/绘图器。它们不能与脚本同时占用端口。
如果串口监视器不方便使用，可在 VM 关闭时仅按第8步运行脚本并查看 STATUS/OK JOG；四台电机仍必须拆开。没有有效状态或命令被拒绝，就停止并回报。

## 第6步：设置万用表
1. 黑表笔插表上的 COM 孔。
2. 红表笔插标 V/Ω 的孔，绝不能留在 mA/A/10A 电流孔。
3. 选择直流电压：V⎓（直线配虚线），不是 V~ 交流档、Ω 电阻档或蜂鸣档。
4. 手动量程表选 20V 档；自动量程表选直流电压模式即可。
5. 黑笔接 D1 模块 GND。最好用绝缘夹子固定；红笔后面一次只碰一个目标针脚。
6. 本轮黑笔始终以 D1 模块 GND 为参考，不接 AO/BO 电机输出。
注意：表上的 COM 是表笔插孔；电脑的 COM9 是串口编号，两者没有关系。

## 第7步：先测不用点动的三项
确认电机都已拆开、投掷动力断开、固件锁定。打开原来的降压输入电源，给 D1 VM 供电。使用此前已确认的 6V设置，不回到12V。
保留 USB 逻辑供电。

黑笔保持 D1 GND，红笔依次测：
1. VM：应约6V。先确认这里不是12V；如果不是约6V，断电检查降压输出与VM连线。
2. VCC：应约3.3V。记下读数。
3. PWMB：应约3.3V。记下读数。

这些“约”是本次设置的预期，不是严格的合格公差。3.2V接近预期；0V、0.4V、1.xV等明显偏离时先停；VCC若测到5V/6V等也先停，检查接线是否符合3.3V逻辑方案。
异常就断开 VM 和 USB，再查对应线两端；不要带电挪线，也不要用改限流/升压掩盖它。

## 第8步：一个测点跑一次，先测 BIN2
前一步正常才继续。仍然不接电机。
1. 黑笔固定在D1 GND。
2. 红笔点D1 BIN2，放稳。
3. 让队友执行命令最方便；一人操作时，放稳探针后再执行，不用手持探针抢时间。
4. 在PowerShell复制：

```powershell
& '.\.venv\Scripts\python.exe' '.\host\jog_loop.py' --port COM9 --wheel RL --duty 128 --seconds 20
```

将COM9替换成第5步确认的实际端口。
5. 看终端是否反复出现：
```text
OK JOG RL duty=128 duration=800ms
```
这表示命令已接受；单有脚本“已发送”的计数不够。
6. 在这20秒里只看BIN2，记录稳定值或变化范围。正向RL点动时它应接近0V。
7. 读完可按Ctrl+C提前结束，不必等满20秒。
8. 等脚本退出，核对：
```text
OK STOP LOCKED
STATUS ... control=LOCKED STBY=0 duty=0,0,0,0
```
以收到的板上回复为准；脚本自己的“已尝试STOP”不等于板上确认。
9. 若反复ERR command/interlock，按Ctrl+C，保存输出，本次测量无效，先排查在线/按键/模式条件。
10. 若报“打不开COM”，不要改接线；先关闭串口监视器、检查端口号。
11. 没收到停止回复、脚本失去响应或不清楚当前状态时，断开VM，再拔USB，停止本轮。

## 第9步：用同一命令依次测 BIN1、STBY
每换一个测点都按同样顺序：
- 等脚本完全退出，确认LOCKED。
- 为移动探针而关闭VM并拔USB；调整夹子/探针。
- 重新接USB，待PS2在线、按钮松开，再开6V VM。
- 运行第8步同一条20秒命令，只测这一个点。
- 记录范围，按Ctrl+C退出并确认锁定。

BIN1应出现非零输出变化。万用表可能显示不到1.6V或时高时低；不要求它固定1.6V。
STBY在有效点动期间高、停止间隙低，表读数可能波动。不要将一次读到0V等同于整段没有使能。
如果不方便在端子直接测，先断电固定绝缘测量夹。夹到面包板远端不等于测到模块针脚。

本轮不把BO1–BO2无负载的PWM读数当坏板判据，因为输出高阻阶段与表计刷新会造成歧义。输入补齐后，再设计固定电平输出检验。

## 第10步：结束与回报
1. 结束脚本，确认LOCKED。
2. 关闭VM输入电源。
3. 拔USB。
4. 本轮先不接回电机；要恢复时也只能在全部断电后恢复。

按下面填写实际值，不预填期望：
```text
实际串口：COM__
四台电机已拆开：是/否
投掷动力断开：是/否
VM（静止）：__V
VCC（静止）：__V
PWMB（静止）：__V
BIN2（RL点动期间）：__V，稳定/范围__
BIN1（RL点动期间）：__V，稳定/范围__
STBY（RL点动期间）：__V，稳定/范围__
是否收到OK JOG RL：是/否
是否收到OK STOP LOCKED：是/否

```

## 如何据结果继续
- VCC异常：查ESP32 3V3到模块VCC的整条线。
- PWMB异常：查3V3轨、第9排和模块PWMB之间的连接。
- 正向RL时BIN2明显非零/也变化：查GPIO19→BIN2与GPIO18→BIN1的错位/短接；先保存读数，断电查线。
- BIN1始终0且命令确实接受：查GPIO18→BIN1路径与针脚测量；不由一次表读数直接判定GPIO坏。
- STBY始终低：查GPIO33→共用STBY路径与点动是否真正使能。
- 输入没有明显异常：下一轮做主控控制线隔离后的静态驱动输出测试，再与D2同条件对照；仍不直接判坏板。
