## 0. 一句话结论

原文第 1、6 节的核心结论是：四轮独立控制要 **13 根输出**，单个 ESP32 装不下，因此全车集成**必须加 MCP23017 扩展器或第二块主控**。

本建议指出：改用**每路 2 根线**的接法，只需 **8 + 1 = 9 根**，**单个 ESP32 就够，不需要任何新模块**。

代价是三条实打实的取舍（§3），需要你权衡后决定。

---

## 1. 分歧点：13 根 vs 9 根

| | 原文（3 线/路） | 本建议（2 线/路） |
|---|---|---|
| 每路电机用线 | PWM + IN1 + IN2 = 3 | IN1 + IN2 = 2 |
| 四路方向线 | 8 | 8 |
| 四路 PWM 线 | 4 | **0**（PWM 脚钉在高电平） |
| 共用 STBY | 1 | 1 |
| **合计输出** | **13** | **9** |
| 装进单个 ESP32？ | ✗ 不可行 | ✓ 刚好 |
| 额外硬件 | **MCP23017 或第二块 ESP32** | 无 |
| 面包板的作用 | 分线位置 | 分线位置 |

原文的算法（13 根）没问题，本建议的算法（9 根）也没问题 —— **差别只在于 `PWMA`/`PWMB` 这两个脚要不要占 GPIO。**

## 2. 两线法的原理

TB6612FNG 的输入输出功能表：

| STBY | IN1 | IN2 | PWM | 输出 |
|---|---|---|---|---|
| L | × | × | × | 待机，**全部高阻** |
| H | L | L | H | 停止（高阻，**滑行**） |
| H | H | L | H | 正转 |
| H | L | H | H | 反转 |
| H | H | H | H | **短路制动** |
| H | 任意 | 任意 | L | 短路制动 |

**关键在最后两行与倒数第三行：**

- `PWM=L` 时无论 IN 是什么，输出都是短路制动 → 也就是说 **`PWM` 脚是"总闸"**。
- 而 `IN1=IN2=L` 是**高阻滑行**，不是制动。

所以把 `PWMA`/`PWMB` **钉在高电平**（逻辑轨），只用两个 IN 脚打 PWM：

| 想要 | AIN1 | AIN2 | 结果 |
|---|---|---|---|
| 正转调速 | PWM 方波 | 常低 | 高电平时正转，低电平时滑行 → **占空比 = 平均转速** |
| 反转调速 | 常低 | PWM 方波 | 高电平时反转，低电平时滑行 |
| 停止 | 常低 | 常低 | 高阻滑行 |
| **主动制动** | **常高** | **常高** | **短路制动** |

**注意最后一行：两线法并没有丢掉制动能力** —— 需要刹车时把两个 IN 脚同时拉常高即可。丢掉的只是"调制期间用制动而非滑行"这一种模式。

### 2.1 为什么 STBY 下拉是必需的，不是"建议"

原文第 3 节写"建议加 10kΩ 下拉"。本建议认为应当**升级为强制项**，原因在上表：

`PWMA`/`PWMB` 钉在常高时，**只要两个 IN 脚出现"一高一低"，电机就全速转**。而：

- ESP32 从上电到 `setup()` 执行之间约 **200–400ms**，所有 GPIO 都是**高阻**；
- 高阻的 CMOS 输入电平**不确定**，可能被读成高；
- 于是上电瞬间可能出现 `IN1=H, IN2=L` → **四个轮子在你还没执行到一行代码时就已经全速转了**。

`STBY` 拉低时芯片处于待机、输出全部高阻 —— **一个 10kΩ 下拉就能盖住整个启动窗口**。

这比给 8 个 IN 脚各加下拉更省（1 个电阻 vs 8 个），但**不是二选一**：有电阻就两处都装，双保险。

## 3. 代价（不隐瞒）

| # | 代价 | 说明 | 严重度 |
|---|---|---|---|
| 1 | **PWM 通道从 4 路变成 8 路** | 8 路电机 + SimpleFOC 的 3 路 = 11 ≤ ESP32 的 16 路 LEDC。余量只剩 5 | 低 |
| 2 | **调制期是滑行而非制动** | 低速线性度略差、不能边调速边制动。但可随时用"两 IN 常高"主动制动 | 低 |
| 3 | **9 根引脚一根不剩** | 见 §3.1，这是**唯一需要认真权衡**的一条 | **高** |

### 3.1 第 3 条：引脚彻底用满，舵机没地方了

9 根正好把可用引脚吃干净。而物资表里有 **MG995/MG996R 舵机**，如果投球/落球机构要用舵机，**就一个 GPIO 都不剩**（舵机需要独立的 PWM 信号线，TB6612 驱动不了舵机）。

三条出路，按推荐顺序：

1. **舵机走奇果派 PCA9685 板**（如果那块板你手上有）：16 路 PWM 全走 I2C，只占 21/22 两根，与 AS5600（0x36）地址不同可共总线，且**不占任何新 GPIO**。代价是又依赖 I2C —— 见 §6.3 的担心。
2. **用两线法 + 减少一个轮子的功能**：不可行，四轮独立是麦轮的硬要求。
3. **回到原文的三线法 + MCP23017**：方向线走扩展器，ESP32 只出 4 路 PWM + STBY = 5 根，腾出 4 根给舵机。代价是增加模块 + I2C 依赖。

**如果你已经确定要用舵机，第 3 条（即原文方案）反而更合适** —— 这是我从一开始就认同原文的一点。

## 4. 引脚分配（两线法，全车集成）

前提：投掷固件 `PS2Catapult` **保持在原引脚上不动**。

| 用途 | GPIO | 备注 |
|---|---|---|
| AS5600 SDA / SCL | 21 / 22 | 投掷固件占用 |
| DRV8313 IN1/IN2/IN3 / EN | 25 / 26 / 27 / 14 | 投掷固件占用 |
| PS2 CLK/CS/CMD/DAT | 2 / 4 / 12 / 13 | 投掷固件占用 |
| **左前 FL**（D1-A） | **16 / 17** | |
| **左后 RL**（D1-B） | **18 / 19** | |
| **右前 FR**（D2-A） | **23 / 32** | |
| **右后 RR**（D2-B） | **15 / 5** | |
| **STBY（两板共用）** | **33** + **10kΩ 下拉** | 非 strap 脚 |

已排除：GPIO6–11（Flash）、34–39（仅输入）、1/3（UART0 串口）、0（BOOT 键）。

### 4.1 两处刻意的安排

1. **STBY 放 GPIO33** —— 它不是启动配置脚。算一下就知道**这不是必需、而是求稳**：ESP32 内部上拉约 45kΩ，外部 10kΩ 下拉与它分压得 `3.3 × 10/(10+45) ≈ 0.6V`，低于逻辑低门限（约 0.825V），**所以 10k 下拉本来就赢得了内部上拉，启动窗口在任何 strap 脚上也盖得住**。放 Non-strap 脚的好处只是少两个小麻烦：不必让下拉白扛 ~0.06mA 灌电流，也不必担心影响 strap 脚自身的启动功能。
2. **右后轮的两个 IN 脚 = GPIO15 + GPIO5**（两个 strap 脚）。这两个脚启动时都有**内部上拉**，所以该路开机状态是 `IN1=H, IN2=H` → 按功能表是**短路制动**（安全），而不会出现"一高一低"的驱动状态。**不花一分钱消掉一个隐患。**

> ⚠️ 一个**条件性**副作用（本方案不会遇到，但换脚时会）：GPIO15 的 strap 功能是 MTDO，**若它在上电时被拉低，ROM 启动日志会被静音**（`ets Jul 29 2019...` 那几行）。本方案里 GPIO15 是方向输入脚、只被内部上拉拉高，**日志正常**。但如果你把带 10k 下拉的 STBY 换到 GPIO15 上，日志就会消失 —— 应用程序自己的 `Serial.print` 不受影响，仓库"烧录后读串口验证"的流程照常可用，但启动异常时会少几行线索。**所以别为了省一个引脚把 STBY 挪到 GPIO15。**

## 5. 面包板排线（沿用原文 a–j / 1–30 坐标系）

坐标与原文一致，可直接叠在它的表上看差异。左组 a–e 接 D1（左板），右组 f–j 接 D2（右板）。

| 面包板行号 | 左组 a–e：接 D1（左板） | 右组 f–j：接 D2（右板） |
|---:|---|---|
| 3 | AIN1 / **GPIO16**（左前） | AIN1 / **GPIO23**（右前） |
| 4 | AIN2 / **GPIO17** | AIN2 / **GPIO32** |
| 5 | BIN1 / **GPIO18**（左后） | BIN1 / **GPIO15**（右后） |
| 6 | BIN2 / **GPIO19** | BIN2 / **GPIO5** |
| 7 | STBY / **GPIO33** ← 经 e7–f7 桥接到右组 | STBY / **GPIO33**（同一条线） |
| 8 | PWMA → **3.3V 轨**（不再是信号行） | PWMA → **3.3V 轨** |
| 9 | PWMB → **3.3V 轨** | PWMB → **3.3V 轨** |
| 13 | AS5600 SDA / GPIO21 | 留空 |
| 14 | AS5600 SCL / GPIO22 | 留空 |

- 第 7 行放 **10kΩ 下拉**（c7 → 接地轨），这是 §2.1 的强制项。
- 第 8、9 行不再是信号，只是从 3.3V 轨引出两个"常高"点。**仍保留这两行**，是为了让本表能和原文逐行对齐。
- **除第 7 行外，不要跨中央隔槽连接**（原文此条同样适用）。
- 相对原文，左侧信号行从 7 行减为 5 行，**第 10–12、15 行以上空出来了** —— 如果以后要用舵机（走配置 1 的 PCA9685 则不需要），这里有位置。

### 5.1 必查：面包板电源轨是否分段

原文第 5 节已提"长轨是否分段"，这里强调它是**最常见的"明明接了却不通"**：

上电前用万用表确认 **+/− 轨两端都导通**（很多面包板在中间断开）。不通就用一根短跳线跨接。另外确认：**每排 a–e 相通、f–j 相通、中央隔槽两侧不通**。

## 6. 对原文其余部分的意见

### 6.1 §3 电源接法：结论赞同，理由需要加固

原文写：

> 不要照商品图把 VCC 和 STBY 接 5V 后再用 ESP32 3.3V 直接控制。芯片 VCC 工作范围 2.7–5.5V，**高电平门限最小为 0.7×VCC**；VCC=5V 时需至少 3.5V。VCC=3.3V 可匹配 ESP32。

**结论（VCC 用 3.3V）我完全赞同，而且建议照做。** 但"门限 = 0.7×VCC"这个具体数值我**没能独立核实** —— 检索只返回了来源列表，取不到数据手册正文，所以不敢转述为事实。存在两种读法：

| 读法 | VCC=5V 时门限 | 3.3V 逻辑能否驱动 |
|---|---|---|
| (a) VIH = 0.7 × VCC | 3.5V | ✗ 不行 |
| (b) VIH = 2.0V 固定（TTL 兼容） | 2.0V | ✓ 可以 |

**关键在于：不论哪种读法，VCC=3.3V 都是安全的。**

- 读法 (a)：门限 = 0.7×3.3 = **2.31V** < 3.3V ✓
- 读法 (b)：门限 = **2.0V** < 3.3V ✓

所以原文的**结论在两种解释下都成立**，这正是它值得照做的原因 —— 用 3.3V 等于把这个问题**绕开**，而不是赌某一个数值。

补一条原文没提的好处：**VCC=3.3V 让芯片的逻辑轨和 ESP32 的供电轨是同一个网络**，于是不存在 5V 轨与 3.3V 引脚共存的风险，我这两线法的 `PWMA`/`PWMB` 也就可以**直接钉在这条 3.3V 轨上**，不需要另设 5V 轨（原文把右 + 轨留给"已确认需 5V 的逻辑设备"，本方案里它不是必需项）。

> ⚠️ 但要接受一个偏差：**板子丝印写的是"逻辑电压 (VCC) 5V"**。VCC=3.3V 在芯片规格内（2.7–5.5V），却低于板子的标称。首次上电必须**实测确认**：给方向脚、量输出端是否真的动作（见 §7 第 2 步）。

### 6.2 §7 验收流程：赞同，补两点

原文四步流程（断电核对 → 只开逻辑测 STBY=0V → 架空逐轮低占空比点动 → 验停止/复位/断联 → 验前后旋转横移）**完整且正确**，照做即可。补：

1. **两线法要多测一步**：`PWMA`/`PWMB` 是否真的稳定在 3.3V。这两个脚一旦虚接成低电平，**该路电机将完全不动**（PWM=低 = 一直短路制动），现象是"方向线怎么动都没反应"，很容易误判成板子坏。量一下这两个脚，能省半天。
2. **验 `IN1=IN2=H` 的制动**：因为 §2 最后一行用它当刹车，值得单独确认一次确实表现为"快速停住"而不是"滑行"。

### 6.3 §6 全车集成：⚠️ 我对 MCP23017 这一条有实质担心

原文建议"补一块 3.3V 的 MCP23017 I2C 扩展模块，方向和待机走扩展器"。

**这个设计本身是对的**，但我担心的是它依赖 **I2C 总线 —— 也就是当前有间歇性故障的那两根线**。

`docs/诊断记录-第一阶段.md` 与 `docs/阻塞问题与烧录实测.md` 记录得非常明确：

- SDA（GPIO21）的上拉**时有时无**：同一台机器、同一固件、相隔 30 秒，`I2C pulldown` 从 `SDA=1` 变成 `SDA=0`，而 SCL 始终稳定；
- 换线、低速、交换引脚、内部上拉都试过，均未恢复；
- 结论是 **SDA 路径间歇性开路（接触不良）**，且**尚未做通断实测**。

把四个轮子的**方向控制**放到这条总线上，意味着：**SDA 一抖，四个轮子的方向同时失去控制**。这比 AS5600 读不到角度的后果严重得多 —— 角度丢了是会拒绝使能，方向丢了是**车会乱走**。

因此本建议的排序是：

1. **先用两线法，走纯 GPIO，完全绕开 I2C**（本方案的全部价值在这里：它让底盘不依赖那根坏线）；
2. **如果一定要用扩展器，先把 SDA 修好** —— 按 `docs/诊断记录-第一阶段.md` 第 5 节的优先级 1 做断电通断实测（判据：`G` 命令显示 **`共 2 个引脚有外部上拉`**），并通过"手转整圈 + 静置连续验证无 I2C 错误"；
3. 扩展器的地址还必须核对不与 AS5600 的 `0x36` 冲突（原文已提，此处呼应）。

> 原文第 6 节末尾那句"**扩展器不能代替硬件急停；I2C 故障时应由主控将 STBY 拉低，停止四轮**"写得好 —— 在两线法里，这条退路更短：STBY 是**纯 GPIO 直连**的，不经过任何总线。

### 6.4 §1 两阶段思路：赞同

"先用现有 ESP32 单独调底盘 → 再整合投掷"这个两阶段划分是对的：麦轮极性校正本来就要反复改线，隔离出来调更省事。原文第 4 节那张"底盘单独调试 GPIO 表"**复用了投掷的引脚**（25/26/27/14/13/4），这在该阶段是合理的，因为原文明确要求先断开投掷控制线与 PS2。

**唯一提醒**：该表的 `GPIO13`（D2 BIN2）与 `GPIO4`（STBY）分别是 PS2 的 DAT 和 CS。**整合时必须整体切换到 §4 的分配**，不能沿用。原文已用"不能把下面的底盘 GPIO 表直接叠加到旧投掷接线上"提醒了这一点，本建议再标一次，因为这是最容易被漏掉的一步。

## 7. 我建议的做法（决策顺序）

```
你有奇果派 PCA9685 板吗？
├─ 有 → 先修 SDA（诊断记录优先级 1）
│        修好后：4 路电机 + 最多 8 路舵机全走 I2C，零新增 GPIO
│        这条路最省引脚，代价是依赖那根线
└─ 没有 / 或想绕开 I2C 故障
     └─ 需要舵机吗？
        ├─ 不需要 → 【两线法】9 根刚好，不加任何模块（本建议）
        └─ 需要   → 【三线法 + MCP23017】（原文方案）
                    但必须先修好 SDA，且先确认舵机数量
```

**不论走哪条，第一步都一样**：先按 `docs/诊断记录-第一阶段.md` 把 SDA 那根线修掉。它是当前唯一一个**会同时影响投掷和底盘**的故障。

## 8. 本建议尚未确认的事项

诚实列出，避免被当成已验证结论：

| # | 事项 | 怎么确认 |
|---|---|---|
| 1 | TB6612 逻辑门限究竟是 0.7×VCC 还是 2.0V 固定 | 查 [东芝 TB6612FNG 数据手册](https://toshiba-semicon-storage.com/info/TB6612FNG_datasheet_ja_20141001.pdf) 电气特性表。（结论不受影响，见 §6.1） |
| 2 | 面包板实物是否 a–e / f–j 相通、长轨是否分段 | 万用表通断实测（§5.1） |
| 3 | GPIO16/17/23 等是否引出、是否被板载器件占用 | 核对 ESP32 实物丝印 |
| 4 | VCC=3.3V 时芯片是否真的正常工作 | 首次上电实测输出动作（§7 第 2 步） |
| 5 | 麦轮电机的额定/堵转电流 | 查电机参数，再对比单路 1.2A（原文第 3 节已提，此处呼应） |
| 6 | 是否已有奇果派 PCA9685 板、是否需要舵机 | 你确认 —— 这决定 §7 走哪条分支 |

**本次交付仅为接线与引脚规划文档，没有烧录、没有启动电机、没有修改任何固件。**
