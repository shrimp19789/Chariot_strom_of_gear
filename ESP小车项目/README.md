# ESP 小车项目 —— ESP32 + 2804 无刷电机 (FOC)

本目录是 `ESP32-2804-FOC-guide.md` 的**可执行版本**：那份 guide 里的两段示例程序
已经变成真正能编译、能烧录的固件，另外配了一个带自检的一键烧录程序。

---

## 一、你现在这块板子（实测，不是猜的）

```
串口   : COM9   USB-SERIAL CH340   (USB ID 1a86:7523)
芯片   : ESP32-D0WD-V3 (revision v3.1)   ← 即 ESP32-WROOM-32E 那一档
Flash  : 4 MB
MAC    : 08:a6:f7:a8:95:94
FQBN   : esp32:esp32:esp32   (ESP32 Dev Module)
```

### ⚠️ 一个必须知道的矛盾

接线照片上写的主控是 **ESP32-S3**，但插在电脑上的这块**实测是经典 ESP32**
（`ESP32-D0WD-V3`）。这两者 FQBN 不同（`esp32s3` vs `esp32`），**选错会烧出跑不起来的固件**。

`flash.ps1` 的做法是：**先用 esptool 问芯片，拿实测结果决定编译目标**，并且在
检测到"照片写 S3、实际不是 S3"时主动提示。所以这个矛盾不会导致烧错。

### 板上原本烧的是什么

烧录前我读了串口，原本跑的是之前会话留下的：

```
=== 2804 OPEN-LOOP MOTOR TEST ===
wiring: IN1/2/3 -> 25/26/27 , EN -> 14 , GND common
safety: start with USB only, connect 12V AFTER the countdown
```

**这条输出同时确认了引脚分配**（见下）。烧录本项目的固件会覆盖它。

## 二、已确认的硬件参数

### 引脚（两处独立证据一致）

| 信号 | GPIO | 证据 |
|---|---:|---|
| IN1 | 25 | 板上原固件自报 + guide 建议值 |
| IN2 | 26 | 同上 |
| IN3 | 27 | 同上 |
| EN | 14 | 同上 |
| SDA | 21 | ESP32 默认 I2C（待第一阶段实测确认） |
| SCL | 22 | 同上 |
| FLT | 不接 | 厂家接线说明 |
| GND | 共地 | 必须，driver 与编码器都要和 ESP32 共地 |

### 2804 电机（来自规格图 OCR）

| 项目 | 值 |
|---|---|
| 槽极数 | 12 槽 14 极 → **12N14P** |
| **极对数** | **7 对** ← 代码里的 `POLE_PAIRS` |
| 额定电压 | 12V（可用 7.4–16VDC） |
| 定子直径 / 高度 | 28mm / 4mm |
| 重量 | 37g |
| 相电阻 Rs | 2.3Ω |
| 相电感 Ls | 0.86mH |
| **额定电流** | **0.5A**（1A 以内温升正常） |
| **最大电流** | **2A** |
| KV | 220 |
| 空载转速 | 2600 RPM @ 12V |
| 扭矩 | 300 g·cm (0.03 N·m) |
| 工作温度 | 0 ~ 45℃ |

### 驱动板与编码器

- 驱动芯片：**TI DRV8313**（2.5A 三相半桥驱动）
  - 这是从驱动板实物照片上 OCR 出来的丝印（`DRV8313`），与 guide 里"芯片疑似 DRV8313"一致，现已确认
  - 板上丝印引脚：`GND / FLT / EN / IN1 / IN2 / IN3`；板号 `13018714A_P1` / `13018714A_P2`
  - 对应 DRV8313 的：`EN1/EN2/EN3` = 板上 `IN1/IN2/IN3`（三路 PWM 输入）、
    `nSLEEP` = 板上 `EN`（总使能）、`nFAULT` = 板上 `FLT`（开漏故障输出，所以"不接"是对的）
- 功率输入 **8.2~24V**（与 DRV8313 的 8~60V 区间相容）
- 编码器：**AS5600**，I2C 地址 **0x36**
- 降压模块：`6V~24V-IN` / `5V-OUT` / `3V3-OUT` / `VADJ-OUT`

## 四、怎么烧

```powershell
cd D:\dsh\1001\ESP小车项目\tools

.\flash.ps1 -List                 # 只看串口和芯片，什么都不烧（安全）
.\flash.ps1 -Stage 1              # 烧第一阶段 AS5600 测试（推荐先做这个）
.\flash.ps1 -Stage 2              # 烧第二阶段 FOC 闭环测试
.\flash.ps1 -Stage 1 -CompileOnly # 只编译不烧录
.\flash.ps1 -Stage 1 -SkipVerify  # 烧完不去读串口
.\flash.ps1 -Stage 1 -UploadSpeed 115200   # 上传老失败时降速重试
```

`flash.ps1` 每一步都会校验：

1. 列串口，按 USB 芯片型号识别（CH340 / CP210x / FTDI / 乐鑫原生），**自动排除蓝牙串口**
2. 用 esptool 读芯片型号、Flash 大小、MAC —— 认不出芯片就报错，不瞎猜
3. 按**实测芯片**决定 FQBN
4. 编译 + 烧录
5. 烧完复位并读串口，把板子的输出直接显示出来

> 走错串口是这类项目最常见的翻车点，所以脚本**宁可不自动选、也不乱选**：
> 认不出 USB 芯片的串口会直接报错让你用 `-Port COMx` 指定。

## 五、两个阶段的用法

### 第一阶段：AS5600 测试（先做这个）

**前提：请断开驱动板功率电源（8.2~24V 输入），只留 USB 给 ESP32 供电。**

烧完直接看串口输出：

```
raw=1234  deg=108.46  MD=1  ML=0  MH=0  changes=57
```

合格表现（guide 第 4 节）：

- 用手慢慢转一圈，`raw` 大致走满 **0~4095**，跨零点正常回绕
- 转子不动时读数基本稳定
- `MD=1` 检测到磁铁；`ML=1` 磁场偏弱；`MH=1` 磁场偏强

我在原程序上加了两点诊断：找不到 `0x36` 时**自动扫描全总线**（区分"线没通"还是"地址不对"），
以及打印 `changes` 计数（判断磁铁是否真的随转子在动）。

### 第二阶段：FOC 闭环空载测试

源码里 `CONFIG_CONFIRMED = false`，所以**现在烧进去是安全锁定状态**：只会打印 `LOCKED`，
电机不会动，也不会校准。等你核对完下面清单再改成 `true` 重新烧录。

核对清单（源码顶部注释里也有）：

- [ ] 接线逐根核对过（IN1=25 IN2=26 IN3=27 EN=14 SDA=21 SCL=22，共地）
- [ ] **驱动板 EN 的有效极性已确认**（程序假定高电平有效）
- [ ] 用万用表实测了驱动板输入电压，并把 `SUPPLY_VOLTAGE` 改成实测值
- [ ] 电机 U/V/W 已接好，电机牢固固定
- [ ] 编码器磁铁随转子转动且中心对准芯片（第一阶段 `MD=1`）
- [ ] **首次测试不装投掷杆**
- [ ] 把 `CONFIG_CONFIRMED` 改成 `true`

串口命令（115200）：

| 键 | 作用 |
|---|---|
| `c` | 对齐/校准（**电机会动**） |
| `+` | 目标 +1 rad/s（约 +9.5 rpm）试转，最多 5 秒 |
| `-` | 目标 −1 rad/s 反向试转，最多 5 秒 |
| `0` | 请求零速度 |
| `x` | 立即软件禁用 |

## 六、安全须知（这部分请务必看完）

### 为什么电机电压上限只给 1.0V

这颗 2804 的相电阻约 **2.3Ω**，额定电流 **0.5A**，最大 **2A**。堵转电流 ≈ 施加电压 ÷ Rs：

| 施加电压 | 堵转电流 | 判断 |
|---:|---:|---|
| **1.0V** | ≈ 0.43A | 与额定 0.5A 相当，**安全** |
| 3.0V | ≈ 1.3A | 已超额定，靠"1A 以内温升正常"硬扛 |
| 12.0V | ≈ **5.2A** | **远超 2A 上限，37g 小电机会烧** |

本程序**没有电流采样**，是电压模式 FOC，**软件无法限制真实电流**。
所以：**不要因为"电机不转"就直接加大 `MOTOR_VOLTAGE_LIMIT`**，
先断电查接线、极对数、编码器。

### 其他

- **软件停止不能替代断开驱动功率电源。**
- 校准时串口命令响应会变慢；要紧急停止就**断开驱动功率电源**。
- 驱动板功率输入是 8.2~24V，**不要把 5V/3.3V 逻辑电源当成功率输入**。
- 编码器供电有"接 5V"和"接 3.3V 但要去掉 R3"的说法冲突。ESP32 的 SDA/SCL 是
  3.3V 电平，**5V 上拉需要电平转换或按厂家资料改模块**，别直连。
- 首次上传建议**断开降压模块到 ESP32 的 5V 线**（USB 供电、共地保留），
  避免外部 5V 和 USB 同时灌进开发板。
- 电机电流走合适的电源线，**不要走杜邦线**。

### 关于 EN 极性（第 1 项）的结论

从驱动板照片 OCR 出芯片是 **DRV8313**，于是可以按数据手册判断，不用再猜：

| 板上丝印 | DRV8313 实际引脚 | 含义 |
|---|---|---|
| `EN` | `nSLEEP` | 总使能。**低 = 睡眠（输出高阻）**，高 = 正常工作 |
| `IN1/IN2/IN3` | `EN1/EN2/EN3` | 三相 PWM 输入（这就是为什么用 `BLDCDriver3PWM`） |
| `FLT` | `nFAULT` | 开漏故障输出（所以"不接"是对的） |

**结论：guide 的假定（EN 高电平有效）是对的**，SimpleFOC 的 `BLDCDriver3PWM`
默认 `enable_active_high = true` 也正好匹配。

**更关键的是安全性**：把 `EN` 拉低 = `nSLEEP` 拉低 = **芯片睡眠、三相输出高阻**，
这是最安全的状态。所以**第一阶段的"EN 拉低"无论哪种解释都是安全的**。

> 唯一残留的不确定性：万一板上加了反相三极管级，极性会翻转。但即便如此，
> 只要第一阶段按 guide 要求**断开驱动功率电源**，就不会有任何问题。

## 八、排查表

| 现象 | 优先检查 |
|---|---|
| `flash.ps1` 找不到串口 | 数据线（有些只能充电）、CH340 驱动、板子插好没 |
| 串口被占用 / 打不开 | 关掉 Arduino IDE 的串口监视器 |
| 上传卡在下载阶段 | `-UploadSpeed 115200` 降速；必要时手动按 BOOT/EN |
| 第一阶段 `0x36` 无应答 | 程序会自动扫总线：扫不到=线/供电问题；扫到别的地址=芯片不对 |
| `MD=0` | 磁铁没对准或没装；`ML=1`/`MH=1` 是磁场太弱/太强 |
| `raw` 不变或乱跳 | 磁铁是否随转子转动、固定是否牢、磁场状态 |
| 第二阶段打印 `LOCKED` | 正常，`CONFIG_CONFIRMED` 还是 `false` |
| 对齐失败 | 编码器角度、极对数、相线顺序、EN 极性、驱动供电、磁铁位置 |
| 抖动/不转却发热 | **立刻断电**，不要加大电压 |
| ESP32 重启 | 供电跌落、共地、电流回路、接触不良、电机干扰 |
