`Start Arduino IDE.cmd` 里有一条注释值得抄下来：

### 4.2 COM9 的进一步证据

- 注册表仍保留设备记录：
  `HKLM\SYSTEM\CurrentControlSet\Enum\USB\VID_1A86&PID_7523\5&347eed33&0&5`
- `VID_1A86 : PID_7523` = **CH340** USB 转串口芯片，
  ESP32 开发板（以及 UNO 兼容板）上最常见的那颗。
- 状态 `Unknown` = **设备当前不在场**（之前插过、驱动装过、现在拔了）。

**结论：CH340 驱动已经装好了**（`D:\Download\arduino\drivers\CH341SER.EXE` 也备着，
备用 CP210x 驱动在 `drivers\CP210x\`）。插上板子后应当能直接识别，
若真的没驱动再运行 `drivers\latest\Install-Latest-Drivers.cmd`。

### 5.2 新增了一个 ESP32 版的驱动库

**问题**：厂家那份 `QGPMakerMotorShield_Lib_V5.2` **无法在 ESP32 上编译**：

```
PinChangeInterrupt.h:30:10: fatal error: avr/io.h: No such file or directory
```

因为该库目录里捆了 AVR 专用的 `PinChangeInterrupt*.cpp`（编码器功能用），
而 arduino-cli 会把库目录下所有 `.cpp` 都拿去编译 → ESP32 必然失败。

**这也是为什么厂家在资料包里**（`_net_test\7gp\v56\`）**单独放了一个 `esp32` 目录**。
对比后确认：

| 文件 | V5.2 版 vs 厂商 ESP32 版 |
|---|---|
| `QGPMaker_MotorShield.cpp` / `.h` | **完全相同**（SHA-256 一致） |
| `Adafruit_MS_PWMServoDriver.h` | **完全相同** |
| `Adafruit_MS_PWMServoDriver.cpp` | 内容相同，**仅换行符不同**（CRLF vs LF） |
| `PinChangeInterrupt*.cpp/.h` | 厂商 ESP32 版**故意不提供** |

**解决办法**：新增一个带 `library.properties`、且 `architectures=esp32` 的库：

```
D:\Download\arduino\sketchbook\libraries\QGPMakerMotorShield_ESP32\
├── library.properties          (architectures=esp32)
└── src\
    ├── QGPMaker_MotorShield.h        ← 取自厂商 ESP32 版
    ├── QGPMaker_MotorShield.cpp
    ├── Adafruit_MS_PWMServoDriver.h
    └── Adafruit_MS_PWMServoDriver.cpp
```

**为什么这样最干净**：arduino-cli 会按目标架构选库。
实测已验证两条路都正常：

```
Alternatives for QGPMaker_MotorShield.h:
  [QGPMakerMotorShield_Lib_V5.2  QGPMakerMotorShield ESP32@5.6.0]
  → 给 ESP32 编译时选中 QGPMakerMotorShield ESP32@5.6.0   ✔
  → 给 UNO 编译时仍用原 V5.2 库（DCMotorTest 编译通过）   ✔
```

也就是说：**你原来的 UNO 工作流完全不受影响**，ESP32 也能编了。
